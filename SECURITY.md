# Security Policy

## Supported Versions

Security fixes are applied to the latest version of Psychelog on the `main` branch and the live app at the address listed in the [README](README.md).

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, report them privately using either option:

1. **GitHub private reporting** — open a report at
   [github.com/lyfmail-official/psychelog/security/advisories/new](https://github.com/lyfmail-official/psychelog/security/advisories/new).
2. **Email** — contact@lyfmail.com with the subject line `Security: Psychelog`.

Please include:

- A description of the issue and its potential impact
- Steps to reproduce, or a proof of concept
- The affected page, feature, or file
- Your browser, device, and operating system

## What to Expect

- We aim to acknowledge your report within **7 days**.
- We will keep you updated while we investigate and fix the issue.
- We will credit you in the release notes if you wish, once the issue is fixed.

## Scope

In scope: the Psychelog source code in this repository and the live app.

Out of scope: social engineering, physical attacks, denial-of-service testing, and vulnerabilities in third-party services or in browsers themselves.

## Responsible Disclosure

Please give us reasonable time to fix an issue before disclosing it publicly, and avoid accessing or modifying other people's data while testing.

Thank you for helping keep Psychelog and its users safe.
